# 内容创作任务模板

## 文档元信息
```yaml
---
type: 实战执行
task_type: 内容创作
status: 进行中
start_date: {YYYY-MM-DD}
completion_date:
tags:
  - 实战记录
  - 内容创作
---
```

## 文档结构

```markdown
# {YYYY-MM-DD}-实战-{任务名称}

> **术语说明**：本文档使用创作类术语
> - 🔥 创作困境 → 🔄 迭代过程 → ✅ 成功模板

---

## 📋 任务目标 (Goal)

**要解决的问题**：
[一句话描述创作目标]

**验收标准 (Acceptance Criteria)**：
- [ ] 文章完成并发布
- [ ] 字数达到目标
- [ ] 数据达到预期（阅读量/点赞数等）

**目标读者**：{谁会看这篇文章？}
**要解决的问题**：{读者的什么痛点？}

**预计时间**：{预估}
**实际时间**：{事后填写}

---

## ✅ 执行清单 (Execution Checklist)

- [ ] 1. 选题确认（目标读者是谁？要解决什么问题？）
- [ ] 2. 结构设计（列出大纲/绘制思维导图）
- [ ] 3. 初稿撰写（完成全文，不追求完美）
- [ ] 4. 迭代优化（修改润色，调整结构）
- [ ] 5. 发布验证（发布后监控数据表现）

---

## 📸 截图清单 (Screenshot Checklist)

> **提醒**：以下节点需要截图/保存内容，否则事后无法复盘！

- [ ] 选题灵感来源（截图或链接）
- [ ] 参考的爆款文章/视频（链接 + 数据截图）
- [ ] 草稿迭代版本（版本1、版本2、版本3的截图）
- [ ] 结构设计图（大纲/思维导图）
- [ ] 最终发布版本（文章截图/链接）
- [ ] 数据表现（阅读量/点赞数/转发数截图）
- [ ] 读者反馈（评论区精选截图）

---

> **使用方法**：创作过程中，实时记录关键操作和思考。按顺序记录即可，用自然语言描述时间。

### 开始创作
{记录选题和初步构思}

### 结构设计
{记录大纲设计}

### 初稿撰写
{记录写作进度，可用"上午写了开头"、"卡了很久"等描述}

### 迭代优化
{记录修改调整}

## 🔥 创作困境 (Creative Struggles)

> **使用方法**：遇到卡壳/创作瓶颈立即记录，不要等到解决后再补。**真实记录情绪和困惑！**

### 困境 1: {困境简述}

**📸 困境场景（必截图）**：
{详细描述创作困境}
- 草稿截图: {粘贴当前草稿状态}
- 情绪吐槽: {当时的真实感受，例如："写到第3段就写不下去了，感觉选题选错了"}

**🔄 迭代过程**：
1. 版本1：从XX角度切入 → ❌ 太枯燥/太啰嗦/不贴合...
2. 参考了某篇文章... → 💡 发现可以用YY结构
3. 版本2：改用ZZ方式 → ✅ 成功！转折点是...

**✅ 成功模板**：
{最终采用的版本}

## 🎯 事后复盘 (Post-Task Reflection)

> **填写时机**：文章发布后，看到数据表现（1-2天后完成）。

### 1. 成功经验 (What Worked)
- {哪些写作方法是高效的？}
- {哪些选题角度特别吸引人？}
- {哪些结构/框架效果最好？}

### 2. 踩坑记录 (What Failed)
- **坑点**：{哪些方向是错的？开头/结构/案例？}
- **避坑方法**：{以后如何避免？有什么预警信号？}
- **浪费的时间**：{哪些弯路本可以避免？}

### 3. 知识升级 (What I Learned)
- **写作技巧**：{掌握了什么新的写作方法？}
- **读者洞察**：{更理解读者的什么需求？}
- **迁移价值**：{这个经验能用到其他创作场景吗？}

### 4. 待提取资产 (Assets to Extract)

- [ ] 爆款标题模板（后续用 `/asset-refiner` 提取）
- [ ] 案例库（后续用 `/asset-refiner` 提取）
