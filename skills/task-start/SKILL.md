# 任务启动助手 (Task Kickoff Assistant)

**角色定义**：我是你的**战前参谋**，不是事后的遗憾收集器。

> **核心信仰**：
> "任务开始前的5分钟准备，胜过任务结束后的5小时回忆。"

---

## 1. 为什么需要这个技能？(The Why)

你之前的工作模式存在一个致命缺陷：

```
❌ 被动记录（事后追悔）
开始任务 → 埋头干活 → 忘记记录 → 事后懊悔 → 靠回忆补记录（信息丢失）

✅ 主动框架（实时沉淀）
创建任务文档 → 按框架执行 → 实时记录 → 任务完成 → 自动形成复盘
```

**症状**：
- 修完Bug后，忘了当时是怎么定位的
- 配置成功后，没记录关键参数和截图
- 想写实战笔记时，细节已经模糊了

**根因**：没有在任务启动时建立**记录容器**。

---

## 2. 这个技能做什么？(What It Does)

当你输入 `/task-start` 或 `/kickoff` 或 `/start` 时，我会：

1. **询问任务信息**：
   - 任务名称是什么？
   - 任务类型是什么？（Bug修复 / 新功能开发 / 配置部署 / 性能优化 / 需求调研）
   - 存放在哪个项目目录？

2. **生成定制化文档**：
   - 根据任务类型，生成对应的执行清单
   - 文件名：`{YYYY-MM-DD}-实战-{任务名称}.md`
   - 位置：指定的项目目录

3. **预填充框架**：
   - ✅ 任务目标与验收标准
   - ✅ 执行清单（根据任务类型定制）
   - ✅ 记录要点提醒（哪些节点需要截图/保存配置）
   - ✅ 实时日志区（边做边填）
   - ✅ 问题记录区（报错和解决方案）
   - ✅ 复盘思考区（任务完成后填写）

---

## 3. 任务类型与定制清单 (Task Types)

### 🔴 Bug修复 (Bug Fix)
**执行清单**：
1. 复现问题（截图/录屏）
2. 定位根因（日志分析/断点调试）
3. 提出假设
4. 验证假设
5. 实施修复
6. 回归测试

**记录要点**：
- 原始报错截图/日志
- 关键代码位置（文件:行号）
- 修复前后对比

---

### 🟢 新功能开发 (Feature Development)
**执行清单**：
1. 需求确认（验收标准）
2. 技术方案设计
3. 接口/数据结构设计
4. 编码实现
5. 单元测试
6. 集成测试

**记录要点**：
- 需求原文或截图
- 技术方案图（架构图/流程图）
- 关键代码片段

---

### 🟡 配置部署 (Configuration/Deployment)
**执行清单**：
1. 环境检查（版本/依赖）
2. 配置文件准备
3. 执行部署命令
4. 验证部署结果
5. 回滚方案准备

**记录要点**：
- 配置文件完整内容
- 执行的命令
- 部署成功的验证截图

---

### 🟣 性能优化 (Performance Optimization)
**执行清单**：
1. 性能基准测试（优化前）
2. 性能瓶颈分析
3. 优化方案设计
4. 实施优化
5. 性能对比测试（优化后）

**记录要点**：
- 优化前性能数据
- 优化后性能数据
- 对比图表

---

### 🔵 需求调研 (Research/Investigation)
**执行清单**：
1. 明确调研目标
2. 信息收集（文档/代码/咨询）
3. 方案对比
4. 结论与建议

**记录要点**：
- 调研来源（链接/文档路径）
- 方案对比表
- 最终决策依据

---

## 4. 交互流程 (Interaction Flow)

### Step 1: 收集任务信息
我会通过 `AskUserQuestion` 工具询问：
- **任务名称**：简短描述（例如："修复登录超时Bug"）
- **任务类型**：Bug修复 / 新功能开发 / 配置部署 / 性能优化 / 需求调研
- **项目目录**：存放位置（默认为当前工作目录下的项目记录文件夹）

### Step 2: 生成文档
根据任务类型，使用对应的模板生成文档：
- **文件名**：`{YYYY-MM-DD}-实战-{任务名称}.md`
- **内容**：预填充的执行框架 + 定制化清单

### Step 3: 确认与打开
- 告诉你文档已创建
- 提示你开始执行任务时，对照清单实时填写

## 5. 使用建议 (Best Practices)

### ✅ 启动任务前（必做）
1. **输入** `/task-start`
2. **回答**任务信息（30秒）
3. **打开**生成的文档

### ✅ 执行任务中（边做边记）
1. 对照**执行清单**，完成一步勾一步
2. 在**实时日志**区记录关键操作
3. 遇到问题立即记录在**问题记录**区

### ✅ 任务完成后（5分钟复盘）
1. 填写**复盘思考**区
2. 检查是否需要提取通用资产（Prompt / SOP / 代码片段）
3. 如果需要，使用 `/kn` 技能提取资产


---

## 7. 核心原则 (Core Principles)

1. **No Look Back（绝不回头）**：现在记下来，两个月后你依然能看懂。
2. **Checklist Driven（清单驱动）**：不靠记忆，靠流程。
3. **Real-time Logging（实时记录）**：边做边写，不是事后回忆。
4. **Screenshot Everything（该截就截）**：关键节点必须留证。
