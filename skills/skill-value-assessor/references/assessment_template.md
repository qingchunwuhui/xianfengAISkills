# Skill 评估记录模板

本模板用于保存 Skill 孵化评估的历史记录，方便季度复盘和决策分析。

---

## 评估记录格式

每次评估后，可以将以下内容追加到评估历史文件中：

```markdown
## [任务名称] - YYYY-MM-DD

**任务描述**：[简要描述这是什么任务]

**评估得分**：
- 认知摩擦力：[X]/5 分 - [简要理由]
- 结构化程度：[X]/5 分 - [简要理由]
- 复用价值：  [X]/5 分 - [简要理由]
- **总分**：[XX]/15 分

**判定结果**：[立即封装 / 优化后封装 / 保持人工]

**决策理由**：
[为什么做出这个决定？有什么特殊考虑？]

**后续行动**：
- [ ] [如果是"立即封装"，这里记录下一步行动]
- [ ] [如果是"优化后封装"，这里记录优化计划]

**复盘提醒**：[设置3个月后的复盘日期]

---
```

## 示例记录

### 示例 1：立即封装案例

```markdown
## 5W1H盲点扫描 - 2026-02-10

**任务描述**：在重要决策或文档完成前，检查 6 个维度（Who/When/Where/What/Why/How）是否有遗漏。

**评估得分**：
- 认知摩擦力：5/5 分 - 人脑天生偷懒，很难强迫自己每次都检查完整
- 结构化程度：5/5 分 - 有明确的 6 个检查维度和清单
- 复用价值：  4/5 分 - 任何重要决策都需要，漏了可能导致项目失败
- **总分**：14/15 分

**判定结果**：✅ 立即封装 (Must Have)

**决策理由**：
- 这是典型的高认知负载 + 高结构化任务
- 每次手动检查都有遗漏风险
- 做成 Skill 后可以强制执行完整检查

**后续行动**：
- [x] 使用 /skill-creator 创建 Skill
- [ ] 测试 Skill 在实际项目中的效果
- [ ] 收集团队成员的使用反馈

**复盘提醒**：2026-05-10（3个月后）

**复盘结果**（待填写）：
[3个月后填写：这个 Skill 实际使用频率如何？是否真的有用？]

---
```

### 示例 2：优化后封装案例

```markdown
## 整理浏览器书签 - 2026-02-10

**任务描述**：将杂乱的书签按主题分类整理到不同文件夹。

**评估得分**：
- 认知摩擦力：3/5 分 - 有点繁琐，但不算太痛苦
- 结构化程度：2/5 分 - **瓶颈**：分类标准不清晰，每次都要重新判断
- 复用价值：  3/5 分 - 确实需要整理，但频率不高
- **总分**：8/15 分

**判定结果**：⚠️ 优化后封装 (Should Have)

**决策理由**：
- 主要瓶颈在"结构化程度"（2分）
- 如果能先定义清晰的分类标准，可以提升到 4-5 分
- 优化后预计总分：3 + 5 + 3 = 11 分 → 适合封装

**优化计划**：
- [ ] 定义清晰的书签分类标准（采用 PARA 方法）
- [ ] 手工用新标准整理 2-3 次，验证标准是否够用
- [ ] 把分类规则写成文档
- [ ] 重新评估，如果结构化程度达到 4-5 分，再做成 Skill

**复盘提醒**：2026-03-10（1个月后检查优化进展）

---
```

### 示例 3：保持人工案例

```markdown
## 给女朋友写情书 - 2026-02-10

**任务描述**：在特定纪念日，写一封感人的情书。

**评估得分**：
- 认知摩擦力：4/5 分 - 确实有压力，怕写不好
- 结构化程度：1/5 分 - **致命短板**：完全依赖个性化情感，无法标准化
- 复用价值：  2/5 分 - 只有特定纪念日才写，频率很低
- **总分**：7/15 分

**判定结果**：❌ 保持人工 (Won't Do)

**决策理由**：
- 结构化程度太低（1分），AI 无法有效执行
- 情书需要真实情感和共同记忆，标准化会失去灵魂
- 即使 AI 能写出语法正确的文字，也缺少个性化细节

**替代方案**：
- 可以让 AI 提供"情书开头灵感"或"表达爱意的句子示例"
- 但不做成完全自动化的 Skill

**关键学习**：创意性强、个性化需求高的任务不适合自动化。

---
```

## 复盘检查清单

每季度（或自定义周期）复盘时，使用以下清单：

### 高分 Skill（12-15分）复盘

- [ ] 这个 Skill 实际使用频率如何？（比预期高 / 符合预期 / 比预期低）
- [ ] 是否真的减轻了认知负担？
- [ ] 有没有发现新的适用场景？
- [ ] 是否需要优化或补充功能？
- [ ] 是否值得推荐给团队成员？

### 中分任务（8-11分）复盘

- [ ] 优化计划是否执行？
- [ ] 优化后是否达到预期效果？
- [ ] 现在是否可以重新评估并做成 Skill？
- [ ] 如果仍未优化，是否还有必要？

### 低分任务（0-7分）复盘

- [ ] 后续是否有任何变化（频率提高、流程标准化等）？
- [ ] 是否值得重新评估？
- [ ] 有没有找到更好的替代方案？

## 使用建议

1. **每次评估后立即记录** - 趁记忆新鲜，记录决策理由
2. **设置复盘提醒** - 3个月后检查高分 Skill 是否真的有用
3. **定期统计分析** - 每季度分析决策模式，发现自己的判断偏差
4. **团队共享**（可选）- 如果团队成员也在创建 Skill，可以分享评估记录
