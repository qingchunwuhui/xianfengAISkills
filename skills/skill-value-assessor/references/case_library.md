# Skill 孵化案例库

本文档收录典型的 Skill 孵化评估案例，用于帮助用户校准评分标准。

---

## ✅ 高分案例（12-15分）：立即封装

### 案例 1：5W1H 全景盲点扫描法

**任务描述**：在重要决策或文档完成前,检查 6 个维度（Who/When/Where/What/Why/How）是否有遗漏。

**评估结果**：
- **认知摩擦力**：5分
  - 人脑天生偷懒，很难强迫自己每次都检查 6 个维度
  - 容易"假装检查了"但实际跳过
  - 需要持续专注，稍有疲劳就容易遗漏

- **结构化程度**：5分
  - 有明确的 6 个检查维度
  - 每个维度都有具体的检查清单
  - 可以完全用 if-then 规则描述

- **复用价值**：4分
  - 任何重要决策/文档都需要
  - 一旦漏了盲点可能导致项目失败
  - 虽然不是每天都用，但错误代价很高

**总分：14分**

**判定：立即封装** ✅

**关键学习**：这是 Skill 的典型甜蜜区 —— 既费脑、又标准化、又重要。

### 案例 2：代码提交规范检查

**任务描述**：在 git commit 前，检查提交信息格式、文件完整性、测试覆盖率等。

**评估结果**：
- **认知摩擦力**：4分
  - 需要记住多个检查点（格式/文件/测试）
  - 容易因为赶时间而跳过
  - 总是想"先提交再说"

- **结构化程度**：5分
  - 有明确的检查清单（格式规范、文件清单、测试命令）
  - 完全可以写成自动化脚本

- **复用价值**：5分
  - 每天多次提交代码
  - 不规范的提交会污染 git 历史，影响团队协作

**总分：14分**

**判定：立即封装** ✅

**关键学习**：高频 + 高摩擦 + 完全标准化 = 完美候选者。

### 案例 3：多语言翻译并保持格式

**任务描述**：将技术文档翻译成多种语言，同时保持 Markdown 格式、代码块、链接等不被破坏。

**评估结果**：
- **认知摩擦力**：5分
  - 需要同时关注内容翻译 + 格式保留
  - 容易遗漏特殊字符或破坏链接
  - 极度消耗注意力

- **结构化程度**：4分
  - 有明确的规则（保留代码块、链接、特殊语法）
  - 但不同语言的细微差异需要一些判断

- **复用价值**：4分
  - 如果需要维护多语言文档，频率较高
  - 错误的翻译会导致用户困惑

**总分：13分**

**判定：立即封装** ✅

**关键学习**：即使结构化程度不是满分，只要摩擦力够高，就值得做。

## ⚠️ 中分案例（8-11分）：优化后封装

### 案例 4：整理浏览器书签

**任务描述**：将杂乱的书签按主题分类整理到不同文件夹。

**评估结果**：
- **认知摩擦力**：3分
  - 有点繁琐，但不算太痛苦
  - 主要是"懒得做"而不是"做不来"

- **结构化程度**：2分 ⚠️
  - **瓶颈所在**：分类标准不清晰
  - "这个网页该放哪个文件夹？" —— 每次都要重新判断
  - 没有固定规则

- **复用价值**：3分
  - 确实需要整理，但频率不高
  - 做错了也不会有严重后果

**总分：8分**

**判定：优化后封装** ⚠️

**优化建议**：
1. 先定义清晰的分类标准（如 PARA 方法：Projects/Areas/Resources/Archives）
2. 手工用新标准整理 2-3 次，验证标准是否够用
3. 把分类规则写成清单
4. 然后再交给 AI 做成 Skill（此时结构化程度可提升到 4-5 分）

**优化后预计得分：3 + 5 + 3 = 11分** → 适合封装

**关键学习**：低结构化是最常见的瓶颈，但可以通过优化流程解决。

### 案例 5：写项目周报

**任务描述**：每周五总结本周工作进展，写成周报发给领导。

**评估结果**：
- **认知摩擦力**：4分
  - 需要回忆一周的工作
  - 需要组织语言、突出重点
  - 总想拖到最后一刻

- **结构化程度**：3分
  - 有大致框架（本周完成/下周计划/风险）
  - 但具体内容每次都不同
  - 需要一些判断力（哪些值得写、如何表述）

- **复用价值**：3分
  - 每周做一次（频率一般）
  - 质量影响领导印象（中等重要）

**总分：10分**

**判定：优化后封装** ⚠️

**优化建议**：
1. 建立"工作日志"习惯，每天记录关键事项
2. 定义周报模板和选材标准（如：只写影响团队的事项）
3. 先用模板手写几次，验证有效性
4. 然后做成 Skill（自动从日志提取内容，生成周报草稿）

**关键学习**：中等摩擦 + 中等结构 + 中等频率 = 可以做，但要先优化。

## ❌ 低分案例（0-7分）：保持人工

### 案例 6：给女朋友写情书

**任务描述**：在特定纪念日，写一封感人的情书。

**评估结果**：
- **认知摩擦力**：4分
  - 确实有压力，怕写不好
  - 需要组织情感和语言

- **结构化程度**：1分 ❌
  - **致命短板**：完全依赖个性化情感和共同记忆
  - 每次都不一样，没有固定格式
  - 高度依赖创意和真实情感

- **复用价值**：2分
  - 只有特定纪念日才写
  - 频率很低

**总分：7分**

**判定：保持人工** ❌

**为什么不适合**：
- AI 能写出语法正确的情书，但没有灵魂
- 缺少共同记忆和个性化细节
- 结构化程度太低（1分），AI 无法有效执行

**替代方案**：
- 如果实在需要辅助，可以让 AI 提供"情书写作灵感"或"开头句子参考"
- 但不要做成完全自动化的 Skill

**关键学习**：结构化程度 ≤ 2 分的任务，基本不适合做成 Skill。

### 案例 7：复制粘贴文本

**任务描述**：从 A 文档复制一段文字，粘贴到 B 文档。

**评估结果**：
- **认知摩擦力**：1分
  - 顺手就做了，不费脑子
  - 肌肉记忆操作

- **结构化程度**：5分
  - 完全标准化（Ctrl+C → Ctrl+V）

- **复用价值**：2分
  - 虽然经常做，但每次只需要 2 秒
  - 不值得为此写 Skill

**总分：8分**

**判定：保持人工** ❌

**为什么不适合**：
- 虽然结构化程度高，但**认知摩擦力太低**（1分）
- 手动操作已经足够快
- 做成 Skill 反而增加复杂度（杀鸡用牛刀）

**关键学习**：太简单的任务不值得自动化，即使它很标准化。

---

### 案例 8：创意海报设计

**任务描述**：为新产品设计一张吸引眼球的宣传海报。

**评估结果**：
- **认知摩擦力**：4分
  - 需要创意灵感
  - 需要反复调整和迭代

- **结构化程度**：1分 ❌
  - **致命短板**：完全依赖创意和审美
  - 每次都不一样，没有固定套路
  - "好看"是主观判断，难以标准化

- **复用价值**：3分
  - 如果经常做设计，频率还可以
  - 但质量标准很主观

**总分：8分**

**判定：保持人工** ❌（虽然分数够，但因结构化太低仍不适合）

**为什么不适合**：
- 设计是高度创意性工作
- AI 可以提供灵感或模板，但无法替代人类审美判断

**替代方案**：
- 可以做一个"设计灵感库 Skill"（提供参考案例）
- 但不要做"自动生成海报 Skill"

**关键学习**：即使总分达标，结构化程度太低（1-2分）也不适合自动化。
