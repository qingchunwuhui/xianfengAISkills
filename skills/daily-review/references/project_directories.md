# 项目目录映射

## 核心原则

当日清时决定将内容移动到项目目录时，需要根据内容类型选择合适的目标目录。

---

## 目录结构

基于用户的知识库结构：`E:\OBData\ObsidianDatas\`

### 1. 项目记录目录

**路径**：`E:\OBData\ObsidianDatas\项目记录\`

**适用内容**：
- 具体项目的开发笔记
- 项目相关的问题记录
- 项目相关的决策记录
- 项目相关的实战经验

**子目录**：
- `2026起 个人操作系统升级\` - 个人系统升级相关
  - `知识管理（PKM）\` - 知识管理相关
  - `AI工作流\` - AI工作流相关
  - `写作系统\` - 写作系统相关

**示例**：
```
外来文档：《OAuth最佳实践》
↓ 日清判断：需要在医疗器械项目中验证
↓ 移动到：E:\OBData\ObsidianDatas\项目记录\医疗器械软件开发\
↓ 添加：我的思考 + 实践反思
↓ 提炼为：技能目录中的可复用资产
```

---

**路径**：`E:\OBData\ObsidianDatas\0收集箱日清\`

**适用内容**：

- 这是日清的**源目录**，不是目标目录
- 日清后的内容应该移出这个目录

## 移动决策流程

### 步骤1：判断内容类型

**问自己**：
1. 这是具体项目的内容吗？ → 移动到项目记录
2. 这是已验证的通用技能吗？ → 移动到通用技能（少见）
3. 这是外部资料需要验证吗？ → 移动到项目记录

### 步骤2：选择目标目录

**项目记录目录选择**：
- 医疗器械软件开发相关 → `项目记录\医疗器械软件开发\`
- 公众号写作相关 → `项目记录\公众号写作\`
- 知识管理系统相关 → `项目记录\2026起 个人操作系统升级\知识管理（PKM）\`
- AI工作流相关 → `项目记录\2026起 个人操作系统升级\AI工作流\`

**通用技能目录选择**（少见）：
- 知识管理方法 → `3通用技能\知识管理\`
- AI工具使用 → `3通用技能\AI工具使用\`
- 写作方法 → `3通用技能\写作技能\`
- 软件开发技能 → `3通用技能\软件开发\`

### 步骤3：执行移动

- 移动文件到目标目录
- 记录到日清报告
- 从收集箱中移除

## 注意事项

### 1. 不要跳过项目阶段

❌ **错误做法**：
```
外部文章 → 直接移动到通用技能目录
```

✅ **正确做法**：
```
外部文章 → 移动到项目记录 → 实践验证 → 提炼为技能
```

**原因**：
- 未验证的内容不是技能
- 技能必须是实践验证过的
- 避免技能目录变成"收藏夹"

---

### 2. 项目目录作为"实践容器"

**为什么要放到项目目录？**
- 项目目录天然带有**实际场景**（不是抽象的理论）
- 强制你思考**怎么用到这个项目中**（而非简单收藏）
- 实践反思会暴露**理论与实际的差距**

**类比**：
```
收藏文章 ≈ 买了一本书放书架（永远不看）
放到项目目录 ≈ 带着书去工地干活（边用边学）
```

---

### 3. 聚焦主战场

**两大主战场**：
1. 公众号写作（AI、知识管理、个人成长）
2. 医疗器械软件开发（架构、质量、合规）

**判断标准**：
- 与主战场相关 → 移动到项目记录
- 与主战场无关 → 删除（避免信息囤积）
