# 图片命名规范 (Image Naming Convention)

## 规范格式

### 标准格式
```
序号-关键对象-状态动作.扩展名
```

### 格式说明
- **序号**：两位数字（01-99），强制左补零
- **关键对象**：1-3个汉字，识别主体对象或技术组件
- **状态动作**：2-5个汉字，描述状态或操作
- **分隔符**：使用中划线 `-` 分隔各部分
- **扩展名**：保留原文件扩展名（png/jpg/jpeg/webp/gif）

### 格式示例
```
✅ 正确示例：
01-网络-Ping不通.png
02-Clash-进程运行中.webp
03-配置-环境变量.png
04-网络-验证成功.png
05-PowerShell-安装界面.jpg
06-技能-安装成功.webp
07-错误-日志输出.png
08-界面-配置面板.png

❌ 错误示例：
1-网络-Ping不通.png          （序号未左补零）
01_网络_Ping不通.png          （使用下划线而非中划线）
01-network-ping-fail.png     （使用英文而非中文）
01-网络连接-Ping不通问题.png  （对象过长，超过3个汉字）
01-Ping不通.png              （缺少对象部分）
```

## 序号规则

### 生成方式
**按文档顺序排列**：序号基于图片在markdown文档中的出现顺序生成

### 序号范围
- **01-99**：两位数字，左补零
- 支持最多99张图片

### 序号意义
- **时间线排序**：保证图片按操作流程的时间线排列
- **快速导航**：文件管理器中自动按序号排序
- **还原现场**：复盘时能快速按顺序浏览图片

### 特殊情况
- 如果文档中只有1张图片，序号仍然使用 `01`
- 如果后续追加图片，继续递增序号（如已有01-05，新增从06开始）

## 关键对象提取

### 对象类型

#### 1. 技术组件（优先识别）
```
✅ 推荐使用：
网络、Clash、PowerShell、Git、Docker、Node、Python、WSL
Redis、MySQL、Nginx、Chrome、VSCode、Terminal、命令行

✅ 示例：
上下文："Ping github.com 失败"
  → 对象：网络

上下文："Clash 代理进程正在运行"
  → 对象：Clash

上下文："PowerShell 7 安装界面"
  → 对象：PowerShell
```

#### 2. 操作界面
```
✅ 推荐使用：
安装界面、配置面板、错误提示、终端、控制台、设置、对话框

✅ 示例：
上下文："打开Skills.sh安装界面"
  → 对象：安装界面

上下文："Git配置面板截图"
  → 对象：配置面板
```

#### 3. 抽象概念
```
✅ 推荐使用：
日志、输出、结果、验证、测试、报错、配置、环境

✅ 示例：
上下文："完整的日志输出"
  → 对象：日志

上下文："系统环境变量配置"
  → 对象：环境
```

### 提取原则

#### 保持简洁（1-3个汉字）
```
✅ 优先1-2个汉字：
网络、配置、日志、错误、界面、输出

✅ 最多3个汉字：
PowerShell、安装界面、配置面板

❌ 避免过长：
网络连接工具、PowerShell安装程序
```

#### 优先级规则
1. **技术术语** > 通用名词
2. **具体** > 抽象
3. **简短** > 详细

```
示例：
上下文："Clash代理工具的进程"
  → ✅ Clash（技术术语）
  → ❌ 代理工具（通用名词）

上下文："网络连接验证"
  → ✅ 网络（简短具体）
  → ❌ 网络连接（过于详细）
```

## 状态动作提取

### 三种状态类型

#### Before状态（问题现象）
描述初始状态、错误、失败的场景

```
✅ 推荐用词：
Ping不通、报错、安装失败、无法访问、连接失败、启动报错
权限不足、找不到文件、缺少依赖、版本冲突

✅ 示例：
01-网络-Ping不通.png
02-Git-报错信息.png
03-Node-版本冲突.png
04-Docker-启动失败.png
```

#### Process状态（执行中）
描述正在进行的操作、配置、安装过程

```
✅ 推荐用词：
进程运行中、配置中、安装中、下载中、正在执行
环境变量、参数设置、路径配置

✅ 示例：
01-Clash-进程运行中.webp
02-配置-环境变量.png
03-PowerShell-安装中.jpg
04-Git-路径配置.png
```

#### After状态（成功结果）
描述成功的结果、验证通过、测试成功

```
✅ 推荐用词：
验证成功、安装完成、运行正常、测试通过、配置生效
连接成功、启动成功、识别成功

✅ 示例：
01-网络-验证成功.png
02-技能-安装完成.webp
03-Clash-运行正常.png
04-测试-全部通过.png
```

### 提取原则

#### 保持简洁（2-5个汉字）
```
✅ 优先2-4个汉字：
Ping不通、安装中、验证成功、报错信息

✅ 最多5个汉字：
进程运行中、环境变量配置

❌ 避免过长：
Ping github.com不通、正在下载安装包
```

#### 动作优先原则
如果上下文中有明确的动词，优先使用动词形式

```
示例：
上下文："验证网络连通性成功"
  → ✅ 验证成功（动词+结果）
  → ❌ 成功（仅结果）

上下文："正在配置系统环境变量"
  → ✅ 配置中（动词+进行时）
  → ❌ 环境变量（名词）
```

## 智能跳过规则

### 已规范化文件名的特征

#### 正则匹配模式
```regex
^\d{2}-[\u4e00-\u9fa5]+-[\u4e00-\u9fa5]+\.\w+$
```

#### 匹配说明
- `^\d{2}` - 开头必须是两位数字
- `-` - 中划线分隔
- `[\u4e00-\u9fa5]+` - 至少一个中文字符（关键对象）
- `-` - 中划线分隔
- `[\u4e00-\u9fa5]+` - 至少一个中文字符（状态动作）
- `\.\w+$` - 扩展名

### 跳过示例

```
✅ 符合规范，自动跳过：
01-网络-Ping不通.png
02-Clash-进程运行中.webp
03-配置-环境变量.png
10-PowerShell-安装界面.jpg

❌ 不符合规范，需要处理：
PixPin_2026-02-07_09-55-45.webp     （随机命名）
image123.png                         （通用命名）
screenshot_20260207.png              （日期命名）
1-网络-Ping不通.png                  （序号未左补零）
01_network_ping.png                  （使用英文和下划线）
```

### 跳过逻辑
1. 扫描markdown中所有图片引用
2. 对每个图片文件名进行正则匹配
3. 匹配成功 → 跳过，不处理
4. 匹配失败 → 加入处理队列

## AI语义提取指南

### 上下文窗口
- **范围**：图片引用前后各3-5行文本
- **目的**：理解图片的使用场景和说明

### 提取流程

#### 第1步：识别主体对象
扫描上下文中的：
- 技术术语（Clash、PowerShell、Git等）
- 操作界面（安装界面、配置面板等）
- 抽象概念（日志、输出、结果等）

#### 第2步：识别状态/动作
分析上下文中的：
- 问题描述 → Before状态
- 操作步骤 → Process状态
- 成功结果 → After状态

#### 第3步：生成文件名
```
序号 + - + 对象 + - + 动作 + 扩展名
```

## 批量处理原则

### 处理顺序
1. **按文档顺序**：从上到下扫描markdown，按出现顺序处理
2. **序号递增**：第一张图片为01，第二张为02，依此类推
3. **跳过规范化图片**：已符合规范的图片不改变序号

### 冲突处理
**文件名冲突**：如果目标文件名已存在
```
解决方案：自动添加后缀
01-网络-Ping不通.png  （已存在）
01-网络-Ping不通-1.png （新生成）
01-网络-Ping不通-2.png （再次冲突）
```

### 统计反馈
处理完成后显示：
```markdown
✅ 图片重命名完成
- 总计：10张
- 处理：7张
- 跳过：3张（已规范化）
- 成功：7张
- 失败：0张
```

## 质量标准

### ✅ 优秀命名的特征
1. **语义清晰**：看文件名就知道图片内容
2. **顺序正确**：按时间线排序，符合逻辑
3. **简洁明了**：不超过10个汉字（含分隔符）
4. **易于检索**：使用系统搜索能快速定位

### ❌ 不合格命名的特征
1. **过于抽象**：`01-操作-处理.png`（不知道具体是什么）
2. **过于详细**：`01-网络连接工具-Ping测试不通过.png`（太长）
3. **英文混用**：`01-network-Ping不通.png`（不统一）
4. **缺少上下文**：`01-成功.png`（不知道什么成功了）
