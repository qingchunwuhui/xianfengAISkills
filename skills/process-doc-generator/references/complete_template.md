# 完整过程文档模板 (Complete Process Doc Template)

此模板用于生成高保真的实战过程文档，遵循"黑匣子原则"，确保未来能完整复现。

## 适用场景
- 复杂Bug修复的完整记录
- 技术难题的试错路径还原
- 架构决策的上下文记录
- 需要深度复盘的实战项目

## 填写指南

### Process 章节的关键

**不要写**：
❌ "经过多次尝试，最终解决了问题"（这是事后总结）
❌ "调试了很久，发现是配置问题"（太笼统）

**要写**：
✅ "第一次尝试：修改了 X 配置，报错 Y，说明..."
✅ "第二次尝试：根据报错信息，猜测是 Z 的问题，验证后发现..."
✅ "第三次尝试：参考了官方文档的 W 部分，修改为..."

### Thinking 章节的关键

**不要写**：
❌ "这个问题很有意思"（废话）
❌ "学到了很多"（空洞）

**要写**：
✅ "坑点：之前以为 A 和 B 是一回事，实际上..."
✅ "原理：这个报错的根因是 C 机制，它的工作原理是..."
✅ "认知升级：以前不理解 D，现在明白了 D 本质上是..."

## 黑匣子测试清单

在完成文档后，问自己：
- [ ] 两个月后，我能否只看这个文档就完整复现解决方案？
- [ ] 报错信息完整保留了吗？（包括 Stack Trace）
- [ ] 环境参数清楚了吗？（版本号、OS、依赖）
- [ ] 失败的尝试记录了吗？（避免重复踩坑）
- [ ] 决策上下文清楚了吗？（为什么选A不选B）
- [ ] 底层原理解释了吗？（不只是 how，还有 why）

如果所有答案都是"是" → ✅ 合格的过程文档
如果有任何"否" → ❌ 需要补充完善
