# 轻量版过程文档模板

## 适用场景

轻量版模板适合 **80%** 的日常实战记录场景：

- ✅ 单次操作记录（安装、配置、部署）
- ✅ 工具使用流程
- ✅ 简单问题修复
- ✅ 配置笔记
- ✅ 操作手册

**关键特征**：
- 只有1-2次操作，没有复杂试错
- 重点是"怎么做"，而不是"为什么这样做"
- 需要保留截图和日志，但不需要深度思考分析

## 轻量版 vs 完整版对比

| 维度 | 轻量版 | 完整版 |
|------|-------|--------|
| 适用场景 | 80% 日常操作 | 20% 复杂问题 |
| 操作次数 | 1-2次 | 3次以上真实试错 |
| 思考深度 | 基础避坑 | 深度认知升级 |
| 文档长度 | 1-2页 | 3-5页 |
| 填写时间 | 5-10分钟 | 20-30分钟 |

## 填写指南

### 1. 问题章节

**背景**：一句话说清楚为什么要做这个事
- ✅ "需要全局安装技能，让多平台识别"
- ❌ "想要使用 Skills.sh"（太笼统）

**问题描述**：具体的需求或遇到的问题
- ✅ "在安装完成后出现报错提示，担心安装失败"
- ❌ "遇到问题"（太抽象）

**关键信息**：环境和现象
- 环境：OS、版本、工具
- 现象：报错信息、观察结果

### 2. 解决方案章节

**核心答案**：先给结论，救急用
- ✅ "报错可以忽略，技能已成功安装"
- ❌ "经过排查发现..."（不要绕弯子）

**关键步骤**：一步一步，保留截图
- 每个步骤要具体，不跳步
- **所有截图必须保留**，用 `![[image.png]]` 引用
- 命令要完整，可以直接复制执行

### 3. 避坑指南章节

**坑点**：容易出错的地方
- 不是"注意事项"，而是"为什么会错"
- 说清楚根因和避坑方法

**注意事项**：其他需要记住的点
- 配置细节
- 平台限制
- 版本要求

### 4. 原始记录章节（可选但推荐）

**何时使用**：
- 有完整的日志输出
- 有重要的分析过程
- 有复杂的报错信息

**如何填写**：
- 直接粘贴，不要简化
- 用代码块包裹，保持格式

## 真实性检查清单

在完成文档后，检查：

### 视觉元素
- [ ] 所有截图都保留了（`![[image.png]]` 一个不丢）
- [ ] 每张截图都有说明（这是什么界面）
- [ ] 日志输出完整保留（没有简化为一句话）

### 操作细节
- [ ] 步骤具体（不是"安装技能"，而是"执行 npx skills add..."）
- [ ] 位置清楚（不是"选择选项"，而是"选择第二个 Copy 选项"）
- [ ] 命令完整（可以直接复制执行）

### 真实性
- [ ] 没有虚构操作（只有一次就写一次）
- [ ] 没有添加不存在的分析（没有就不写）
- [ ] 保持原始记录的口语化表达

### 可复现性
- [ ] 两个月后能看截图找到界面
- [ ] 能看日志理解成功和失败
- [ ] 能看步骤完整复现操作

## 实战案例

### 案例：Docker 容器启动

```markdown
# 2026-02-06-Docker容器启动与端口映射

## 问题

**背景**：
需要在本地启动一个 Nginx 容器用于测试前端页面。

**问题描述**：
第一次使用 Docker，不确定如何正确映射端口和挂载目录。

**关键信息**：
- 环境：Windows 11, Docker Desktop 4.25.0
- 目标：访问 http://localhost:8080 能看到页面

---

## 解决方案

**核心答案**：
使用 `docker run` 命令启动容器，通过 `-p` 映射端口，`-v` 挂载目录。

**关键步骤**：

1. **拉取镜像**
   ```bash
   docker pull nginx:latest
   ```

2. **启动容器**
   ```bash
   docker run -d -p 8080:80 -v C:\projects\web:/usr/share/nginx/html --name my-nginx nginx:latest
   ```

   参数说明：
   - `-d`：后台运行
   - `-p 8080:80`：本地8080端口映射到容器80端口
   - `-v`：挂载本地目录到容器
   - `--name`：给容器命名

3. **验证成功**
   访问 http://localhost:8080
   ![[nginx-success.png]]

---

## 避坑指南

**坑点**：端口已被占用
- 根因：本地8080端口可能已被其他程序使用
- 避坑：使用 `netstat -ano | findstr 8080` 检查端口占用

**注意事项**：
- Windows 路径使用反斜杠 `\`
- 目录挂载需要在 Docker Desktop 设置中允许

---

## 来源
**对话时间**：2026-02-06 15:30
**关键词**：Docker, Nginx, 端口映射, 目录挂载
```

## 何时升级到完整版

如果在记录过程中发现：
- 实际有3次以上的真实试错
- 有深刻的认知升级或洞察
- 需要详细记录决策上下文

那么应该升级到完整版模板（见 `complete_template.md`）

## 总结

轻量版模板的核心原则：

1. **保真优先**：所有截图和日志必须保留
2. **简洁实用**：不强求深度思考，够用就好
3. **真实记录**：有多少材料写多少，不虚构
4. **快速填写**：5-10分钟完成，不增加负担

**记住**：不是所有实战都需要深度复盘，大部分场景用轻量版就够了。
